# 🚀 Cortex v1.2.1 — Don't Panic

> *"Don't Panic."* — in large, friendly letters on the cover of *The Hitchhiker's Guide to the Galaxy*.
>
> Cortex made two promises without checking them. Its core claimed a Python 3.9 floor that only its own CI still ran — until the CI's image stopped shipping 3.9. And before printing `rm -rf`, it showed the checks to some developers and not to others. This patch release keeps both: the floor moves to the Python Cortex actually runs, and everyone about to delete a repository sees what is in it first.

## Fixes

### 🔍 The checks before every removal ([#170](https://github.com/adorey/cortex/issues/170))

Since 1.1.2, before printing the commands that remove a teammate's leftover `cortex/`, Cortex prints three checks:

```bash
git -C cortex status --short --ignored -- . ':(exclude)agents/personalities/.active-*'
git -C cortex log --format='%h %an: %s' HEAD --branches --reflog --not --remotes
git -C cortex stash list
```

Two paths still deleted a repository without them:
- **The migrator whose submodule keeps its repository under `.git/modules/`**, the usual kind. The commands began with `git submodule deinit -f`, which throws away the submodule's changes, and ended with the removal of its repository.
- **A plain clone at `cortex/`.** It got *"Once you have checked it holds nothing of yours"*, then `rm -rf cortex`, with no command to check with.

Both now get the three checks first. A commit or a stash that only that repository held is listed before it goes.

### 🐍 `cortex-core` needs Python 3.11 or later ([#177](https://github.com/adorey/cortex/issues/177))

The core's 3.9 floor served the shim that ran it from source on a host, with that host's system Python (ADR-007). The `cortex` binary replaced the shim in 1.0.0, and a host has needed no Python since. When `ubuntu-latest` became Ubuntu 26.04, which ships no 3.9, the last job that ran it stopped before any test.

The core now needs 3.11 or later, like the CLI and the runtime. CI runs its tests on 3.11 and on the Python that `ubuntu-latest` and `macos-latest` ship, 3.14 today. The macOS job still runs on a file system that ignores case.

## Upgrading

1. Install the binary again: the install line installs the latest release.
2. Set `version = "1.2.1"` in `cortex.toml`.
3. Run `cortex sync`.

Nothing else changes. A host project still needs no Python. A contributor needs 3.11 for the core, as for the CLI.

## Notes

- **#170 comes with tests that fail without it**, checked by mutation, for `cortex init` and `cortex sync`. **#177 is configuration**: the run of its own pull request on both images is its check.
- **ADR-007 is not amended.** It is implemented, and it said the floor would stand only *"until the native binary of ADR-008 makes the question moot"*.
