## Highlights

### 🧪 A framework-agnostic E2E testing capability

New **`agents/capabilities/testing/e2e-testing.md`** — the first card in a new `testing/` category. Six principles, each earned on real work, none tied to a stack:

- **One investment, two uses** — a real E2E doubles as the smoke test you run by hand and the CI regression gate that fails the day someone breaks the path.
- **The fixture is the reusable asset** — the coherent domain graph is the hard part; build it once behind a parameterised factory, treat it as first-class infrastructure.
- **Isolation without teardown cost** — transactional rollback per test, a database per parallel worker.
- **Exercise the real dispatch, not a mocked seam** — run the actual pipeline in-process; mock the dispatch and you've tested your mock.
- **Assert conformity, not presence** — "a row exists" is the weakest assertion; assert schema-/business-validity, or on the mechanism when a broken and a working path share a shape. The E2E face of *"a test can pass for the wrong reason."*
- **Environment parity is real** — a real env var overrides your dotfiles *and* your secrets vault; runtime-only wiring the type-checker never sees is the E2E's to catch.

### ⚙️ Symfony reference — the E2E mechanics

`agents/capabilities/frameworks/symfony.md` gains an **"End-to-end & functional testing"** section: driving the real dispatch in-process (`sync://` transport or a direct handler call), transactional isolation with `DAMADoctrineTestBundle`, `paratest` per-worker databases (`dbname_suffix`), on-demand/factory fixtures — and three Symfony-specific traps an E2E is the first to hit:

- a real (even empty) env var silently overrides `.env.*` **and** `secrets:set` — pin the test value in the test target;
- an entity outside a mapped namespace has **no** entity manager and fails only at runtime, invisible to PHPStan and a green unit suite;
- external binaries (wkhtmltopdf/Snappy…) must exist in the test image or a PDF stage throws mid-pipeline.

Three items added to the Symfony **Quick checklist**.

### 🧭 QA-automation loads the new category

`agents/roles/engineering/qa-automation.md` now lists **`testing/`** among the capability categories to load, so the E2E card reaches the role that owns the pyramid.

## Notes

- Additive knowledge release: one new capability card + category, one new Symfony section, one role-card wiring line — **no runtime behaviour changes**.
- The `testing/` category is deliberately thin for now; it's the home for future cross-cutting testing craft (contract testing, mutation testing, load testing) that shouldn't live under any one framework.
