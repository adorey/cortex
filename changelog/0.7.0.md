# 🚀 Cortex v0.7.0 — End to End

> *"I've calculated the odds of this test catching the bug it's named after. You won't like them."* — Marvin, before the assertion was changed from *exists* to *conforms*.
>
> The big one: the `testing/` category goes from empty to a full **test pyramid** — E2E, component, and the runner mechanics — the Symfony reference gains its E2E craft **and three more traps that pass every gate**, and a new **regulatory-compliance** role joins the roster. Four parallel branches, integrated into one release.

## Highlights

### 🧪 A framework-agnostic E2E testing capability

New **`agents/capabilities/testing/e2e-testing.md`** — the first card in a new `testing/` category. Six principles, each earned on real work, none tied to a stack:

- **One investment, two uses** — a real E2E doubles as the smoke test you run by hand and the CI regression gate that fails the day someone breaks the path.
- **The fixture is the reusable asset** — the coherent domain graph is the hard part; build it once behind a parameterised factory, treat it as first-class infrastructure.
- **Isolation without teardown cost** — transactional rollback per test, a database per parallel worker.
- **Exercise the real dispatch, not a mocked seam** — run the actual pipeline in-process; mock the dispatch and you've tested your mock.
- **Assert conformity, not presence** — "a row exists" is the weakest assertion; assert schema-/business-validity, or on the mechanism when a broken and a working path share a shape.
- **Environment parity is real** — a real env var overrides your dotfiles *and* your secrets vault; runtime-only wiring the type-checker never sees is the E2E's to catch.

A **"Browser/UI E2E adds…"** section extends it for real-browser journeys: select by the accessibility tree, authenticate once and reuse the storage state, page objects behind specs, deterministic waits + trace on retry, and a dedicated CI job so E2E never silently sits disabled.

### 🎨 A component-testing capability + a Vue framework card

The pyramid's **middle rung** lands: new **`agents/capabilities/testing/component-testing.md`** — mount in isolation, query the accessibility tree, cover every state (empty/loading/error/edges), mock at the network boundary, assert a11y with axe, and assert the *mechanism* when a broken and a working render look identical.

New **`agents/capabilities/frameworks/vue.md`** fills the SPA dead-end (`frameworks/` had no SPA card, so "load the project's frontend framework" resolved to nothing): Vue 2/3 + Nuxt, Composition API as the forward-compatible default, a **Testing** section (Vitest v3 / Jest+vue-jest v2, Testing Library, MSW, axe), and an explicit **Vue 2 → 3 / Nuxt 2 → 3 migration** guide.

New workflow **`agents/workflows/engineering/frontend-testing.md`** orchestrates the pyramid (place each check on its rung → component → E2E → CI → *"can it fail for the right reason?"*), and **`lead-frontend`** now declares the `testing/` category (it previously loaded no test card at all), while **`qa-automation`** points `testing/` at both component + e2e cards.

### ⚙️ Symfony reference — E2E mechanics **and three more traps**

`agents/capabilities/frameworks/symfony.md` gains an **"End-to-end & functional testing"** section (real dispatch in-process via `sync://` or a direct handler, `DAMADoctrineTestBundle` isolation, `paratest` per-worker DBs, on-demand fixtures) and **three more traps that pass every gate**:

- **A nullable identity absent in two ways reads as present** — `null === $identity` lets an **empty string** through as a usable identity; the query then matches the wrong (or every) row.
- **A cache key must move when anything that changes visibility changes** — a per-viewer key built from the user id alone serves stale, wrongly-scoped results when a role/permission changes.
- **With `kernel.debug` on, your error templates are never rendered** — a custom error page passes identically with *no* error templates at all; test it with debug off, and don't let the error template extend the main layout.

### 📜 A regulatory-compliance-writer role — **@Pag**

New **`agents/roles/security-compliance/regulatory-compliance-writer.md`** (character **Judiciary Pag / @Pag** — *"Learned, Impartial and Very Relaxed. I have read the annex. All of it."*): produces the **binding documents** a project has to ship — contractual annexes, regulatory plans, audit responses — citing the applicable article before concluding conformity or gap.
