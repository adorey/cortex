# 🚀 Cortex v1.3.0 — Lunchtime Doubly So

> *"Time is an illusion. Lunchtime doubly so."* — Ford Prefect.
>
> A release used to be a tag someone pushed, then a workflow that published what it built, and three dates that drifted apart: the one written, the merge's, the publication's. From this release on, every merge into `main` is a release, checked before it merges and dated the day it merges — in UTC, which is nobody's lunchtime in particular. CI builds it and leaves it as a draft; the maintainer reads it and presses *Publish release*; a guard checks what was published. This release is the first one made that way.

## The release cycle

[ADR-009](https://github.com/xod-labs/cortex/blob/main/docs/adr/ADR-009-release-cycle.md) is implemented. For whoever releases Cortex, a release is now: merge the release pull request, wait for the draft, publish it. Nobody pushes a version tag.

### 🚦 Checked before it merges ([#193](https://github.com/xod-labs/cortex/issues/193), [#194](https://github.com/xod-labs/cortex/issues/194), [#195](https://github.com/xod-labs/cortex/issues/195), [#196](https://github.com/xod-labs/cortex/issues/196))

The `release gate` runs on every pull request into `main`. It passes only when the pull request:
- adds exactly one new version, through its release note;
- has its `CHANGELOG.md` section first, dated the day it merges, in UTC;
- releases a version higher than every release;
- finds no draft waiting.

Its summary names the version. The merge queue runs it again at the moment of merging, and a nightly run re-checks every open pull request, so a date gone stale overnight turns red.

### 📦 Drafted from the merge ([#200](https://github.com/xod-labs/cortex/issues/200), [#201](https://github.com/xod-labs/cortex/issues/201), [#202](https://github.com/xod-labs/cortex/issues/202))

The merge builds the release: the four binaries, the glibc floor, the spec archive, `SHA256SUMS` and an attestation for each. It is left as a draft, created last with its six assets, its target the merged commit. A run that failed makes its own draft again, and nothing else touches a draft. No workflow starts on a tag.

### 🛡️ Checked once published ([#206](https://github.com/xod-labs/cortex/issues/206), [#207](https://github.com/xod-labs/cortex/issues/207), [#208](https://github.com/xod-labs/cortex/issues/208))

The `release guard` checks every publication:
- the tag;
- the provenance of each asset, verified against the tag's commit;
- the six assets and `SHA256SUMS`;
- immutability;
- `latest`.

It keeps `latest` on the highest version that passes. A release that fails its guard never keeps it, and gets an issue: an immutable release cannot be repaired, only replaced by the next patch.

### 🧪 Pre-releases are versions ([#203](https://github.com/xod-labs/cortex/issues/203), [#205](https://github.com/xod-labs/cortex/issues/205))

`X.Y.Z-alpha.N`, `-beta.N` and `-rc.N` are cut by hand from an integration branch, and published like a release. They are never `latest`:
- `install.sh 1.3.0-rc.1` installs one;
- `version = "1.3.0-rc.1"` pins one;
- a binary knows the spec archive of every immutable pre-release.

This release had its candidate first, `1.3.0-rc.1`, as every release that changes the pipeline now does.

### 🌿 Older major versions, on their own branch ([#204](https://github.com/xod-labs/cortex/issues/204))

When 2.0.0 ships, 1.x lives on a branch `1.x` and releases through the same cycle, never as `latest`. A fix released there is carried up to `main`.

## For contributors

- **Commit messages are checked** on every pull request ([#192](https://github.com/xod-labs/cortex/issues/192)). The rules:
  - gitmoji, type, scope;
  - `<subject>` within 72 characters;
  - no body but a `BREAKING CHANGE:` footer;
  - no trailer.

  A subject is written in the present tense and says what the commit does.
- **Every workflow that gates `main` reports one summary check** on every pull request, with no `paths` filter ([#198](https://github.com/xod-labs/cortex/issues/198)). A change that concerns no test skips the tests, and their summary passes.
- **`bin/setup-release.sh`** applies the repository's settings, and `--check` reports drift ([#199](https://github.com/xod-labs/cortex/issues/199)).
- **Every pull request is merged with a merge commit**, and the release steps of CONTRIBUTING are the cycle's ([#209](https://github.com/xod-labs/cortex/issues/209)).

## Upgrading

1. Install the binary again: `curl -fsSL https://raw.githubusercontent.com/xod-labs/cortex/main/install.sh | sh`.
2. Set `version = "1.3.0"` in `cortex.toml`.
3. Run `cortex sync`.

Nothing else changes for a host project.

## Notes

- **The release actions live in this repository** (`.github/actions/`), written to move out as they are when a second project adopts the cycle (ADR-009 §3.9, §7).
- **The cycle ran end to end before it merged**, on a throwaway repository of the organisation: the gate and the merge queue, drafts, publications and the guard. ADR-009 §9 records what that run found and what changed for it.
