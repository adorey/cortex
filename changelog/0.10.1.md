# 🚀 Cortex v0.10.1 — Mostly Harmless

> *"What? Harmless? Is that all it's got to say? Harmless! One word!"* — Arthur Dent, reading the Guide's entry on Earth.
>
> One word can be the whole entry. The 0.10.0 release pull request closed its issues with one word too — one `Closes` in front of twenty-eight numbers — and GitHub, which reads a keyword as applying to the single reference after it, closed one issue and left twenty-seven open. This patch writes down the rule that would have prevented it, in the three places the list gets written.

## Highlights

### 📝 One closing keyword per issue

The delivery process ([`docs/process/adr-implementation.md`](../docs/process/adr-implementation.md#6-commits-and-closing-keywords)) showed several issues behind one keyword: `Closes #42, #43`. That closes #42 and only *mentions* #43. It now says one keyword per issue, one per line:

```text
Closes #42
Closes #43
```

The same rule is stated where the list is actually written:

- the pull-request step of the [`adr-implementation`](../agents/workflows/engineering/adr-implementation.md) workflow;
- the [pull request template](../.github/PULL_REQUEST_TEMPLATE.md), beside its `Closes #` line and in its checklist;
- §9 of the process, for the final `release/adr-NNN-slug` → `main` pull request — the only one whose keywords fire.

## Breaking changes

None. Documentation only: no role, capability, workflow step or runtime behaviour changes. A host project that overrides the `adr-implementation` workflow keeps its own copy of the checklist, and may want the same line.

## Field note

The 27 issues left open by 0.10.0 — the tasks and phases of ADR-007, and the project view (#87, #88) — were closed by hand against #92, with a comment saying why. #86 (reserving `cortex-core` on PyPI) and #89 (the project view as a runtime option) stay open on purpose.
