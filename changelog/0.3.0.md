# 🚀 Cortex v0.3.0 — The runtime comes alive

> *"The Infinite Improbability Drive is a wonderful new method of crossing vast interstellar distances in a mere nothingth of a second, without all that tedious mucking about in hyperspace."* — The Hitchhiker's Guide to the Galaxy
>
> Until now Cortex was a spec *read* by an LLM. This release ships the engine that **executes** it — a deployable, secured, asynchronous runtime.

## TL;DR

`cortex-runtime` (its own package, shipping at `0.1.0`) turns the design-time cascade into a running service: an **agnostic HTTP API** that drives an agentic loop, persists operational state, enforces an optional **security perimeter**, and executes runs **asynchronously** behind a job queue. Three ADRs move to *Accepted* and land in code — **ADR-003 (persistence)**, **ADR-004 (API security)**, **ADR-005 (execution model & resilience)** — plus HMAC webhooks and a one-command Docker/Traefik deploy.

The framework layer (spec, overlays, `setup.sh`) is unchanged and fully backward compatible. Everything here is **additive**, and security/async are **opt-in** (off by default).

## What's new

### 🧠 Cortex Runtime — the executable engine (ADR-002/003)

The MVP of the engine the ADR-002 contract described:

- **Agnostic API** — `POST /run` (+ project-declared aliases), `POST /resolve`, `POST /reply` for human hand-off. The engine never knows it is dealing with a "ticket" — everything is keyed by an opaque `subject`.
- **Agentic loop** with per-request autonomy, anti-recursion (conversation state across invocations), and an identity lock over the `CLAUDE.md` bootstrap.
- **Swappable model backends** — `demo` (no key/CLI, runs the whole wire), `claude-cli` (Pro/Max subscription via `claude setup-token`), and `anthropic-api` (Console key).
- **SecretProvider** discipline + Agent SDK adapter, MCP plumbing for the CLI backend.
- **Run resilience & metrics** — per-run timeout kills a hung agent, CLI actions are audited, and per-run cost/tokens/duration/TTFT are captured.
- **Support-engineer role + triage workflow** as the first end-to-end agent slice.

### 🗄️ Persistence & state (ADR-003 — Accepted)

- The **`StateStore`** boundary (operational state only — spec stays in git, the ADR-003 firewall).
- Three interchangeable backends behind one interface: **InMemory** (tests/ephemeral), **SQLite** (local dev, file or `:memory:`), **PostgreSQL** (production, with a compose service).
- Stores conversation state, run history + monitoring metrics (`cost_usd`, tokens, `num_turns`, `duration_ms`, `ttft_ms`, full `metrics_json`), and an append-only audit log.

### 🔒 API security & trust model (ADR-004 — Accepted)

Opt-in via `CORTEX_AUTH=on`:

- **Bearer** auth on direct + monitoring routes (tokens stored **hashed**), **HMAC** auth on webhooks.
- **`AuthPolicy`** verdict boundary + full-perimeter **connection log** (who tried / verdict / why).
- **Tenant registry** with per-tenant **budget caps** (daily/monthly, computed from `runs.cost_usd`), **rate-limiting**, replay-nonce, and request **idempotency**.
- **Admin CLI** (`python -m cortex_runtime.admin`) + admin routes to manage tenants/tokens, gated by an admin-token capability flag.

### ⚙️ Async execution & resilience (ADR-005 — Accepted)

Opt-in via `CORTEX_ASYNC=on`:

- Run **lifecycle** — `queued → running → {done | failed | skipped}` — so `POST /run` returns `202` with a `run_id` a poller can follow (`?wait=true` keeps the synchronous path).
- A bounded **JobQueue** + worker pool (`CORTEX_MAX_CONCURRENT_RUNS`, `CORTEX_MAX_PENDING_RUNS` → `429` when full).
- **Atomic-claim idempotency** dedups in-flight duplicate submissions.
- **Readiness** — `GET /ready` (store reachable + worker alive, else `503`) vs `/health` liveness; the queue **drains in-flight runs** on shutdown (FastAPI lifespan). Container healthcheck hits `/ready`.

### 🪝 Webhooks

- **`POST /webhook/{source}`** — HMAC-authenticated, with an agnostic payload → run binding (`{source → {tenant, role, workflow?, subject_path}}`) configured via `CORTEX_WEBHOOK_CONFIG`.

### 🐳 Deploy & DevEx

- **Docker image** + local **Traefik** deploy + `docker-compose` (optional Postgres service).
- **CI** — GitHub Actions runs the runtime unit tests on push/PR.
- **JSM MCP server** (`cortex_jsm_mcp`) — read + internal-comment.
- **Optional DBHub MCP** (compose `db` profile) for read-only DB access, config in `config/dbhub/`.
- Named compose project + main container `cortex`.

## Breaking changes

None. The framework layer (spec, overlays, `setup.sh`) is unchanged from v0.2.x and fully backward compatible. The runtime is entirely new and additive; **security (`CORTEX_AUTH`) and async (`CORTEX_ASYNC`) are off by default**.

## Planned for next

## Migration notes

Existing spec/overlay projects: **nothing to do** — the cascade and `setup.sh` behave exactly as in v0.2.x.

To run the engine:

```bash
# quickest smoke test — no key, no CLI
CORTEX_BACKEND=demo python -m cortex_runtime

# or deploy the container stack (see deploy/README.md)
cd deploy && docker compose up -d
```

Key environment knobs: `CORTEX_BACKEND` (`demo` | `claude-cli` | `anthropic-api`), `CORTEX_DATABASE_URL` (Postgres) or `CORTEX_DB` (SQLite file), `CORTEX_AUTH`, `CORTEX_ASYNC`. See [runtime/README.md](runtime/README.md) and the `python -m cortex_runtime` docstring for the full list.
