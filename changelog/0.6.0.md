# 🚀 Cortex v0.6.0 — Trapdoor

> *"Here I am, brain the size of a planet, and they ask me to guard a WHERE clause."* — Marvin, on the five traps that pass every gate.
>
> Two capability cards land in this release, both hardening the Symfony reference: the failures that survive a green test suite, and the one convention that keeps error responses honest across an API. Two parallel branches, one file — merged cleanly here.

## Highlights

### 🔐 Five Symfony security traps that pass every gate

`agents/capabilities/frameworks/symfony.md` gains a **"Security traps that pass every gate"** section — five failures invisible to PHPStan, to a green suite, and to review, each of which cost real time on a real project before being understood:

- **`QueryBuilder::where()` replaces the whole WHERE clause** — a later `where()` silently discards an earlier tenant bound, and a row-level test can't catch it (the rows returned are exactly what the unbounded query returns). Apply bounds last; assert on the generated DQL.
- **`InvalidCsrfTokenException extends AuthenticationException`** — a failed CSRF check answers *302 to the login page*, not 403; a `fetch()` follows the redirect, gets 200 HTML, and reports success for an action that never happened. Convert it in a `kernel.exception` listener above the firewall's priority.
- **`#[Autowire(env:)]` ignores the PHP default** — an undeclared env variable is a 500 at runtime, not a fallback. Declare every variable, including the ones whose feature is off.
- **A password hash reaches the session unless you stop it** — a stateful firewall serialises the user (hash included) into the session, and thus into Redis. `EquatableInterface` *replaces* the built-in crc32c tolerance — `isEqualTo()` must re-implement it, or every request logs the user out.
- **Credential fallbacks resolved in a fixed order** — trying `PRIMARY` then `SECONDARY` breaks the moment both hold the same value (committed `.env` placeholders routinely do); the first match grants the wrong role. Resolve per channel/purpose, never by sequence.

Three items are added to the capability's **Quick checklist**, and a new **`agents/roles/engineering/qa-automation.md`** role card carries the QA-automation angle.

### 📝 Translated API error responses — never hardcoded, never a raw throw

The same card gains a **"Translated error responses"** pattern under *Recommended patterns*: a front-facing API route returns a **translated error response**, not a hardcoded string and not a bare throw. Make the exception message a **translation key**, throw a **translatable HTTP exception** that carries the status (`TranslatableNotFoundHttpException` / `TranslatableAccessDeniedHttpException`), and let a central `kernel.exception` listener resolve it — one consistent, translated, correctly-statused response shape, with no translator injected into the throwing code. Prefer `isGranted(...)` + a translatable 403 over `denyAccessUnlessGranted(...)` (whose message isn't translated).
