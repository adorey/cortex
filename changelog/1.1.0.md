# 🚀 Cortex v1.1.0 — Vogon Poetry

> *"Oh yes," said Arthur, "I thought that some of the metaphysical imagery was really particularly effective."* — Arthur Dent, asked for his review of Vogon poetry, with his life at stake.
>
> A review goes wrong in two ways. Either it praises so that everyone gets through — the metaphysical imagery was really particularly effective — or it never ends, each round opening new points and each fix bringing a new mechanism to review. This release gives Cortex a review workflow that does neither: a blocking point is proven in the code, the reviewer and the author classify with the same legend, and the rounds converge.

## Highlights

### 🔍 `code-review` — one grid for the reviewer and the author

**`agents/workflows/engineering/code-review.md`** has two modes:
- **mode A** reviews someone's pull request;
- **mode B** handles the review of ours.

Both apply the same grid, which is what makes the two sides agree on when a review is done.

- **A shared legend, and no other class:**

  | Class | Handling |
  |---|---|
  | 🔴 **Blocking** — a written convention not followed; an acceptance criterion not covered; a defect introduced that prevents shipping | Fixed before the *Approve* |
  | 🟠 **Major** — a defect introduced and reachable that degrades the use; a path with no test | Fixed before the *Approve* |
  | ⚪ **Minor** | Answered "taken" or "not taken" |
  | ❓ **Doubt** | Answered with proof |
  | 🎫 **Out of scope** | Proposed as an issue |

- **Rules that make a review converge:**
  - a 🔴 or a 🟠 is proven in the code, with a reachable scenario, and introduced by the pull request;
  - a defect older than it becomes an issue;
  - no new mechanism in answer to a review;
  - a decision made is not reopened;
  - from round 2, a new point bears only on the previous round's delta — except a 🔴 introduced by the pull request and missed;
  - a thread at its third round is settled live;
  - fixes are counter-reviewed, adversarially, before they are pushed.
- **The GitHub event each verdict takes:**
  - *Request changes* for a 🔴 or a 🟠;
  - *Comment* for a ❓ alone;
  - *Approve* otherwise.
- **Templates:** one for the published review — the head reviewed, the base, the round, and the verdict first — and one for an issue proposed for arbitration.
- **Roles, not characters:** the workflow names roles, so it reads the same in every theme, and with none.

### 🧭 What mode A checks before reading the diff

Three checks come from reviewing a contributor's pull request that was opened just before 1.0.0:
- **The base is current.** A test merge into the target branch shows a pull request that conflicts, or that leans on files a release removed.
- **The CI is measured, not assumed.** Green checks that ran the target's workflows as they were before the base moved are run again.
- **The description's claims are replayed.** For content an agent reads — a role, a theme, a workflow — that includes a real conversation that loads it.

### 🧩 Overridable, like every workflow

A project that tracks review statuses with labels, or through an issue tracker's states, overrides the workflow with `Semantic: replacement`. So does a project that reviews in another language, or that adds checks of its own. The base carries none of these.

## Upgrading

- **Moving a project to 1.1.0:**
  1. Install the binary again — the install line of 1.0.0 installs the latest.
  2. Set `version = "1.1.0"` in `cortex.toml`.
  3. Run `cortex sync`.

  The Prompt Manager finds the workflow on its next review request.
- **A project that already has its own `agents/workflows/engineering/code-review.md`.** Until now that file was a custom addition. It now shadows a base, and it needs the overlay header — without it, `cortex validate` warns `MISSING_HEADER`, and `--strict` fails:

  ```markdown
  <!-- OVERLAY
       Base: cortex/agents/workflows/engineering/code-review.md
       Scope: workspace
       Semantic: replacement
  -->
  ```

  A file under a service's `agents/` says `Scope: service @alias` instead, with that service's alias — `service @backend`. The file's content stays as it is: with `replacement`, it is read instead of the base, whole.

## Notes

- **1.1.0 ships this workflow alone.**
- **Where the workflow comes from.** It is made generic from a workspace that runs it. Its test in Cortex was a real conversation that activated mode A, and a validator run on a project that has its own `code-review.md`, without the header and with it.
