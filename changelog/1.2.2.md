# 🚀 Cortex v1.2.2 — On Display

> *"There's no point in acting all surprised about it. All the planning charts and demolition orders have been on display at your local planning department in Alpha Centauri for fifty of your Earth years."* — Prostetnic Vogon Jeltz, to the people of Earth.
>
> Cortex moved house: `adorey/cortex` is now [`xod-labs/cortex`](https://github.com/xod-labs/cortex). Unlike the Vogons, it puts the notice where you will see it, at the top of the README. And nothing gets demolished: every old address forwards to the new one. This patch release stops relying on that forwarding. The install scripts, the CLI and the documentation name the new address.

## The move

### 🚚 Cortex lives at `xod-labs/cortex` ([#214](https://github.com/xod-labs/cortex/pull/214))

On 2026-10-30, the repository moved from a personal account to the GitHub organisation of xod labs. GitHub redirects the old address, so the following keep working:
- binaries 1.0.0 to 1.2.1, which have it in their code;
- the old install command;
- clones;
- links to issues and pull requests.

A test repository was moved first, and read again through each old address. Cortex was then read again the same way, once moved:
- the release downloads, `latest` included;
- `raw.githubusercontent.com`;
- the API and git;
- `install.sh` with curl and with wget;
- `cortex sync` downloading a spec from the address built into 1.2.1.

From 1.2.2, the binary downloads from `github.com/xod-labs/cortex/releases`, and prints the new install command. [Moving to xod-labs](https://github.com/xod-labs/cortex/blob/main/docs/moving-to-xod-labs.md) says what to update:
- your install;
- a clone or a fork;
- a script or a CI job that downloads Cortex;
- `CORTEX_RELEASES_URL`.

The history is kept as it was: the changelogs and the ADRs still name `adorey/cortex` where they record what happened there, and their links redirect.

### 🔏 Verifying the attestations

An attestation keeps the repository it was made in. From 1.2.2, the binaries are attested by `xod-labs/cortex`:

```bash
gh attestation verify ~/.cortex/bin/cortex --repo xod-labs/cortex
```

The attestations of 1.0.0 to 1.2.1 name `adorey/cortex`, and GitHub now lists them under the account `adorey`, not under the repository: `--repo adorey/cortex` no longer finds them. Verify them by their owner, pinned to the workflow that signed them:

```bash
gh attestation verify ~/.cortex/bin/cortex --owner adorey --signer-workflow adorey/cortex/.github/workflows/binary.yml
```

## For contributors

- **Release steps 6 and 7 say what immutable releases made final** ([#215](https://github.com/xod-labs/cortex/pull/215)). Since 2026-10-30, a release published from the Releases page can never get its assets, and a trial `X.Y.Z-something` tag leaves a pre-release that stays. Neither is done any more: a release is made by its tag, until the cycle of ADR-009 ([#187](https://github.com/xod-labs/cortex/issues/187)) replaces it.
- **Point your clone at the new address**: `git remote set-url origin git@github.com:xod-labs/cortex.git`.

## Upgrading

1. Install the binary again, from the new address:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/xod-labs/cortex/main/install.sh | sh     # Linux, macOS
   ```

   ```powershell
   irm https://raw.githubusercontent.com/xod-labs/cortex/main/install.ps1 | iex          # Windows PowerShell
   ```

2. Set `version = "1.2.2"` in `cortex.toml` when your team is ready. A project that stays on an earlier version keeps working.
3. Run `cortex sync`.

## Notes

- **ADR-008 is amended** (§9, *2026-10 — the repository moves to xod-labs*): the new address, the old one that must stay free, and the attestations of the versions released before the move.
- **No behaviour changes.** The tests name the new address, and run as before.
- **The macOS binary is built on `macos-latest`**, no longer on `macos-14`: GitHub retires that image on 2026-11-02, and its scheduled outages cancelled this release's first build. The binary still runs on macOS 11 and later, as before.
