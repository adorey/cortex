# 🚀 Cortex v0.8.0 — Marginalia

> *"I've read the comment. It described the line below it. I now know exactly as much as I did before, and I am four seconds older."* — Marvin, on a diff carrying 100 lines of comment for 493 lines of code.
>
> Comment discipline was the one craft rule with no home in cortex: a single orphan bullet in `lead-backend`, nothing at all for `lead-frontend`, and nothing anywhere about **volume**. This release opens a `practices/` category for the rules that belong to no single stack, and starts it with the one every review keeps re-deriving by hand.

## Highlights

### 💬 A `practices/` category, opening with `code-comments`

New **`agents/capabilities/practices/code-comments.md`** — the first card in a category for craft that no `languages/` or `frameworks/` card can own, because it is true whatever the stack. Seven principles:

- **The *why*, not the *what*** — a comment that paraphrases the statement below it is noise; delete it, or rename the thing it was compensating for.
- **Descriptive, not narrative** — the **six-month test**: would this sentence still be true *and* useful in six months, to a reader who never saw the ticket? A comment that narrates the change is false at the next commit while the code stays right.
- **Ambient density — below the rule, never above it** — the project's convention sets the ceiling; the edited file's style calibrates only *underneath* it. A file that breaks the convention is not a precedent, and bringing the rest of it into line is its own change, never a side effect of an unrelated diff.
- **One fact, one home** — documented at the definition, not repeated at every call site.
- **What actually earns a comment** — mirrored invariants, deliberate divergences, third-party workarounds, referenced decisions, non-obvious trade-offs.
- **Markers carry a reference** — a `TODO:` with nothing to resolve it against is a wish, and wishes accumulate.
- **No commented-out code** — git is the history.

The missing rule, in practice, was **volume**: the card is the first place in cortex that says a diff whose comment volume approaches its code volume is a diff whose comments should be read first.

### 🔌 Wired as an unconditional category

`lead-backend`, `lead-frontend`, `architect` and `qa-automation` declare `practices/` as **always load**, on the pattern `security/owasp.md` already established. The category set now carries a distinction worth naming, and `agents/capabilities/README.md` names it: categories resolved **against the project's stack** (`languages/`, `frameworks/`, `databases/`…) versus categories loaded **unconditionally** (`security/`, `practices/`) because the craft they carry is stack-independent.

### 🧩 Per-language mechanics stay per-language

`languages/php`, `languages/typescript` and `frameworks/vue` each gain a short doc-block section covering **their own mechanics only**, pointing back at the shared card rather than restating it — the card applying its own "one fact, one home" rule to itself:

- **PHP** — PHPDoc only where the typed signature cannot say it (collection value types, `@throws`, generics PHPStan consumes); never restating what `declare(strict_types=1)` already guarantees.
- **TypeScript** — the type *is* the documentation; TSDoc earns its place on exported API, and every `as any`, non-null `!` and `eslint-disable-*` carries its reason inline.
- **Vue** — non-obvious props/emits documented; a template comment explains **why a branch exists**, never what the markup renders.

### 📋 What belongs to the host project

`templates/project-context.md.template` now prompts for the two things that are genuinely per-project — the **language** comments are written in, and the **ticket/ADR reference format**. The card states explicitly that those live there and not in cortex, per the "reusable, unmodified, by any project" constraint.

### 🧹 Capability-tree consistency, and a role that loaded nothing

Follow-up to the review of the above:

- The capability tree is refreshed in **all three** places that carry it — `README.md`, `agents/capabilities/README.md` and `docs/getting-started.md`. Two of them still stopped at `symfony` / `mysql`, listing four categories out of eight.
- **`lead-backend` had an empty `🔌 Capabilities` section** — the role loaded no capability whatsoever, in any host project. Restored to the list `agents/capabilities/README.md` has always used as its worked example: `languages/`, `frameworks/`, `databases/`, `security/`, plus `practices/`.
- `practices/` → `practices/code-comments.md` in the four role cards (full path, matching the `security/owasp.md` line above it), and a lost newline in `lead-frontend` that collapsed its whole category list into one run-on line.

## Notes

- Additive knowledge release: one new capability card, one new category, per-language doc-block sections, role wiring and documentation — **no runtime behaviour changes**, no breaking change to the cascade contract.
- One behaviour change worth knowing about for host projects: `lead-backend` previously declared **no** capability category and therefore loaded none. It now loads its language, framework, DBMS, OWASP and the comment card. Projects that had compensated with an overlay can drop it.
