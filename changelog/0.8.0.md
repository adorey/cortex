# 🚀 Cortex v0.8.0 — Front and Center

> *"I've mounted the component in isolation, queried it by role, and asserted every state. It still hates me, but now it hates me deterministically."* — Marvin, discovering the middle rung of the pyramid.
>
> The `testing/` category had a top rung (E2E) and nothing below it, and `frameworks/` had no SPA card at all — so "load the project's frontend framework" dead-ended. This release fills the frontend-testing hole: a component-testing capability, a Vue framework card, the browser side of E2E, a frontend-test workflow, and the role wiring that makes it all load.
>
> **Combined release:** this 0.8.0 also ships the parallel `regulatory-compliance-writer` role + `@Pag` character — see that entry; the two changelog sections are merged at release time.

## Highlights (frontend testing)

### 🧪 A framework-agnostic component-testing capability

New **`agents/capabilities/testing/component-testing.md`** — the middle rung the `testing/` category was missing (it only had `e2e-testing.md`). Six principles, none tied to a stack:

- **Test behavior, not implementation** — query the accessibility tree (role/label/text), interact via user events, never assert on CSS classes or internals.
- **Cover the states** — empty / loading / error / success / edges, not just the happy path.
- **Mock at the boundary** — stub the network (not the store), keep the component real.
- **Isolation + determinism** — mount fresh, freeze time, no live backend (or it's an E2E in disguise).
- **A11y is an assertion** — an `axe` check at the component rung, cheap here, slow in E2E.
- **Assert the mechanism** when a broken and a working render look identical — the component-rung form of *"a test can pass for the wrong reason."*

### ⚙️ A Vue framework card (the dead-end fix)

New **`agents/capabilities/frameworks/vue.md`** — covers Vue 2 (2.7+) and Vue 3 + Nuxt: Composition API as the forward-compatible default, composables over mixins, typed props/store, reactivity hygiene, and a **Testing** section (Vitest on v3 / Jest+vue-jest on v2, Testing Library + user-event, MSW at the boundary, axe) plus an explicit **Vue 2 → 3 / Nuxt 2 → 3 migration** guide (write forward-compatible now; the tests survive the runner swap, the config doesn't). Fills the gap where `lead-frontend`'s "load the project's frontend framework" resolved to nothing.

### 🖥️ Browser/UI E2E — the missing half of `e2e-testing.md`

`agents/capabilities/testing/e2e-testing.md` gains a **"Browser/UI E2E adds…"** section: select by accessibility tree not markup, authenticate once and reuse storage state, a journey per test with page objects behind it, deterministic waits + trace/screenshot on retry, own the critical journeys (not every screen), and wire it as its **own** CI job so it never silently sits disabled.

### 🧭 A frontend-test workflow + role wiring

- New **`agents/workflows/engineering/frontend-testing.md`** — orchestrates the pyramid: place each check on its rung → component tests (states + a11y) → E2E critical journey → CI wiring → *"can it fail for the right reason?"*.
- **`agents/roles/engineering/lead-frontend.md`** now declares the **`testing/`** capability category (it previously loaded no test card at all).
- **`agents/roles/engineering/qa-automation.md`** points `testing/` at both `component-testing` and `e2e-testing`.
