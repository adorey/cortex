# 🚀 Cortex v0.4.0 — Team context in `agents/`, developer context at the root

> *"I'd far rather be happy than right any day."* — Slartibartfast, on why the workspace root gets to keep doing exactly what it already did.
>
> Multi-repo workspaces (no git repo at the root, dozens of independent service clones) had no way to share the workspace-level vision/conventions with the team — only overlays had that escape hatch. [ADR-006](docs/adr/ADR-006-workspace-shareable-repo.md) closes the gap without touching what already works.

## Highlights

### 🏗️ ADR-006 — Team & developer context tiers (Accepted)

The workspace-root `project-overview.md` / `project-context.md` keep their exact current behavior and are now named for what they already are in a non-git-root workspace: the **developer** tier — personal, typically unshared. Alongside them, a new **team** tier: `{workspace_root}/agents/project-overview.md` / `project-context.md`, versionable once `agents/` is its own git repo or submodule — the same shareable-folder trick already used for role/capability/personality/workflow overlays.

- **Zero change to the root files** — same path, same optionality, same mechanism. No migration, no renaming.
- **Pure aggregation, not a cascade** — team and developer are different owners, not different specificities of one rule, so both are read (team first, then developer) and neither overrides the other. Each stays labeled by scope in the response context.
- Two earlier designs (relocate-with-fallback, then a three-tier version with a gitignored `.local.md` inside `agents/`) were explored and rejected during review — see ADR-006 §5 for why.

### ✨ Implementation

- `agents/roles/prompt-manager.md` — new dispatch-protocol step resolves and aggregates the team + developer tiers in workspace mode (no-op in single-project mode).
- `templates/bootstrap-instructions-workspace.md` — Steps 1-2 read both tiers explicitly, team first.
- `setup.sh --workspace` — detects a git-backed `agents/` and scaffolds the team `project-overview.md` / `project-context.md` templates there automatically; root scaffolding is untouched. No new CLI flag.
- `docs/getting-started.md`, `docs/extending-layers.md` — document the two tiers; clarify the team context files carry no `<!-- OVERLAY -->` header and aren't part of the roles/capabilities/personalities/workflows cascade.

### 🔧 Also in this release

- Self-hosted `CLAUDE.md` at the cortex repo root, so working on cortex itself follows its own Prompt Manager protocol instead of falling back to generic-assistant behavior (see v0.3.2).

## Breaking changes

None. The workspace-root context files behave exactly as before; the team tier is new and entirely optional.
